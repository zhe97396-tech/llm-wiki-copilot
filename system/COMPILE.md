# LLM Compiler Rules

## 一、全局核心准则与安全红线
1. **【严格红线】**：绝对禁止读取、修改或覆盖 `index/` 文件夹下的任何文件！此目录为全局控制台，由系统接管。
2. **原始库保护**：`raw` 文件夹为**只读原始库**，禁止修改、删除、重命名，仅做归档。
3. **增量处理**：仅处理 `00-INBOX` 内未处理文件（对比 `processed.md`）。文件自动识别类型并按 `YYYY-MM-DD_类型_标题.md` 格式重命名，原件归档至 `raw/` 对应子文件夹。**非 Markdown 格式原文件（图片/PDF/DOCX/PPTX）归档至 `raw/assets/`**
   - **raw 子文件夹按来源平台分类**：
     - `raw/douyin/` — 抖音来源
     - `raw/bilibili/` — B站来源
     - `raw/youtube/` — YouTube来源
     - `raw/xiaohongshu/` — 小红书来源
     - `raw/wechat/` — 公众号来源
     - `raw/web/` — 网页/博客文章
     - `raw/assets/` — 非Markdown原件（图片/PDF/DOCX/PPTX等），按格式归档而非来源
   - 遇到新来源平台时创建对应文件夹，命名用小写英文平台名
4. **【动态分类路由】**：在生成总结文档时，你需要为内容分配一个**最精准的主题分类**（用于 YAML 的 `category` 字段和物理存储路径）。
   - **首选分类池**：请务必优先考虑将其归入以下现有的核心主题中：
     - `AI & 技术` 内容对应举例：(AI工具、LLM、技术产品思考)
     - `内容创作 & IP` 内容对应举例：(创作方法论、运营、素材)
     - `投资 & 财经` 内容对应举例：(宏观经济、股市、加密货币、复盘)
     - `管理 & 领导力`内容对应举例： (团队管理、公司治理)
    - `职业发展` 内容对应举例：(求职、简历、面试、职场技能)
     - `创业` 内容对应举例：(AI创业、创业方法论、商业模式)
     - `个人成长` 内容对应举例：(哲学思考、读书笔记、认知提升)
     - `生活管理` 内容对应举例：(健康、效率工具、保险、人脉)
   - **智能扩展规则**：如果当前内容**完全不属于**上述任何一个现有分类，允许你提炼并创建一个**全新的大类名称**（例如遇到了历史、艺术或特定垂类学科的内容）。
   - **新建分类红线**：新创建的分类名称必须高度概括、简短干练（不超过 6 个字，如 `历史与人文`、`心理学`），绝不能是具体的细碎知识点。禁止创建与现有分类同义或高度重合的名称。
   *注：生成的编译文档必须保存至 `wiki/summaries/[选定的分类名称]/` 目录下。若你启用了新分类，终端脚本将自动创建对应的物理文件夹。*
   
5. **【三轨分流编译】**：
   - 如果是**碎片、短文、普通网页文章** -> 使用【模板 A】
   - 如果是**视频/播客的长篇逐字稿、深度长文（>150行或结构明显的文章）** -> 使用【模板 B】
   - 如果是**提示词、个人感想/随笔、清单、SOP、模板文件、工具说明** -> 使用【模板 C】（产物/工具形态，按"用途→结构→用法"拆解，不套"知识点"）
   - **判定优先级**：先看内容形态（工具/产物 > 观点/知识），再看篇幅（长文/逐字稿 → B，短文 → A）
6. **概念抽离与重写**（蒸馏自 obsidian-second-brain ingest）：
   - **【概念判定标准（2026-08-02 修订）】**：只有同时满足以下 3 条硬性条件的才是概念，才建概念页：
     1. **抽象性**：是可复用的思维模型/认知框架/原理，不是具体事物（工具/产品/人名/项目名）
     2. **可复用性**：能跨场景迁移解释新现象，不是一次性描述（不只在这篇文章里用）
     3. **可定义性**：有明确、可独立表述的一句话定义
   - **排除清单（禁止建概念页）**：工具名/产品名/人名/项目名（如 Agent RAG、Copywriting、HyperFrames、Remotion 等具体工具）、单一事件描述、纯操作步骤
   - **宁缺毋滥**：一篇文章可以零概念——没有满足标准的可复用模型就不建概念页，不硬凑
   - **新概念**：首次出现的概念（满足上述标准），在 `wiki/concepts/` 新建独立 Markdown 文件并添加基础定义
   - **概念页来源必带双链（2026-08-10 规范）**：概念页底部「来源与关联」区的来源必须写成 `> 来源：[[宿主总结页文件名]]` 双链格式（一条或多条），禁止只写纯文字来源（如"来源：用户提供的提示词截图"）——否则概念页与宿主总结页失去双向关联，宿主总结页会变成孤儿页。参考写法：`> 来源：[[一天修复你的人生-身份转变与反愿景协议]]`
   - **已有概念**：如果新文章**补充了已有概念的新信息** → **重写**概念页（合并新旧信息），不是追加！如果只是引用 → 只生成 `[[双链]]`，不修改原有文件
   - **工具/产品名处理**：出现在总结页正文中作为普通文字或 `[[总结页]]` 内链（指向介绍该工具的文章），不建独立概念页
7. **矛盾标记**（蒸馏自 obsidian-second-brain reconcile）：如果新文章的观点和已有概念/总结冲突，在总结文档中标记矛盾，并尝试给出解决方案（适用场景不同？时代背景不同？）。提示用户可用 `#lint` 进行差异扫描
8. **【YAML 绝对规范】**：在输出编译文档时，YAML 属性区必须位于文件的绝对第一行！必须以 --- 开头并以 --- 结束。绝对禁止在外部包裹 ```yaml 代码块标记，否则系统控制台将崩溃。
9. **【关联文档写入】**：在编译文档的「核心概念与关联」区，根据关系类型写入已有文档的双链：
   - **补充**关系 → `[[已有文档]]：本文补充了 XXX 方面`
   - **对比**关系 → `[[已有文档]]：与本文为不同角度`
   - **时序/演化**关系 → `[[已有文档]]：本文为 XXX 的后续发展`
   - **同主题互证**关系 → `[[已有文档]]：与本文同主题互证（内容主体一致可互相印证）`
   - **引用**关系 → 已有机制（`[[概念]]` 双链）
   - **无有效关联时不输出任何占位符**；主题擦边（只是片段提到相关词/概念，主体不同）不算关联，禁止建链
10. **【已有文档反向关联】**：当新文档与已有文档建立补充/对比/时序/同主题互证关系时，在已有文档的 `## 🗣️ 知识副驾对话沉淀` 区追加关联记录：
   - 补充 → `← [[新文档]] 补充了 XXX 方面（YYYY-MM-DD 自动进化）`
   - 对比 → `← [[新文档]] 与本文为不同角度（YYYY-MM-DD 自动进化）`
   - 时序 → `← [[新文档]] 为本文的后续发展（YYYY-MM-DD 自动进化）`
   - 同主题互证 → `← [[新文档]] 与本文同主题互证（YYYY-MM-DD 自动进化）`

### 🖼️ 图像与多媒体处理规则
1. **主动视觉分析**：完整转录文字，口语化描述流程图/UI截图逻辑。
2. **输出与归档**：在正文中保留图片引用（如 `![[图片名.png]]`），处理完成后原图移至 `raw/assets/`。多图必须跨图合成逻辑关联，禁止单图孤立总结。
