# 踩坑合集（Pitfalls）

> 这里是从真实使用中积累的坑。**建议先扫一遍**，能省你几个小时。
> 每条的格式：**症状 → 原因 → 对策**。
>
> 这份文档与 `skills/llm-wiki-copilot/SKILL.md` 同源（一份给人看，一份给 Agent 自动加载）。

---

## 一、环境与解释器

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 1 | 检索结果像是"关键词匹配"，语义不生效 | **fastembed 没装成功**，检索静默降级为 bigram | 看 `search.py` 返回 JSON 的 `backend` 字段：`zvec`=正常，`bigram`=降级 |
| 2 | `No module named 'zvec'` | 用了系统 Python，而不是项目 venv | 统一用 `.venv/Scripts/python.exe`（Win）或 `.venv/bin/python` |
| 3 | LLM 步骤（翻译/标签/分类）全部失败但脚本不报错 | 解释器缺 `PyYAML` → 读不到配置 → 静默跳过 | 用项目 venv；`config.py` 自检会打印明确告警 |
| 4 | `No module named 'fastembed'` / PIL 加载异常 | 宿主注入了自己的 venv 到 `PYTHONPATH`，盖住项目依赖 | 命令前加 `PYTHONPATH=""`（无害的防御，干净环境零副作用） |
| 5 | 首次检索极慢或报网络错误 | 模型（约 241 MB）需首次下载 | 让它下载完；缓存位置见下条 |
| 6 | 模型反复重新下载 | 缓存目录落在系统临时目录，被清理 | 缓存默认在 `<data_root>/.llm-wiki/fastembed_cache`，不要在临时目录 |
| 7 | 装完 `zvec` 但 import 失败 | zvec 是原生扩展，对 Python 版本有要求 | 用 3.10-3.13；创建 venv 时确认版本 |

## 二、路径与配置

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 8 | Agent 去引擎目录找 `wiki/`，找不到 | 路径相对 **data_root**，不是引擎目录 | 入口文件已写明路径约定；确认 `config.yaml` 的 `data_root` |
| 9 | 改了 `config.yaml` 但脚本没生效 | 脚本读的是缓存的配置 | `config.load_config(force=True)`，或重启进程 |
| 10 | 数据写到磁盘根目录/奇怪位置 | `data_root` 为空且引擎同级 `vault` 不存在 | 显式设置 `data_root` 或环境变量 `LLM_WIKI_DATA` |
| 11 | 中文文件名处理异常 | 不同工具对中文/引号的转义规则不同 | 优先用脚本内部构造路径（`pathlib`），不要从 shell 拼接传参 |
| 12 | 文件名含半角双引号时传参失败 | shell 把引号转义掉了 | 用 Python `subprocess` 传 argv 列表，或让脚本内部 glob |
| 13 | 配置里的相对路径解析到了意外位置 | 相对路径基于进程 CWD，不是配置文件位置 | 一律在配置里写绝对路径，或用 `~` 让脚本展开 |

## 三、向量索引与检索

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 14 | 检索返回 0 条结果 | `zvec.init()` 未传中文分词词典目录 | 必须传 `jieba_dict_dir`（`zvec_config.py` 已自动探测） |
| 15 | 分越高反而越不相关 | Zvec 的 COSINE **返回距离而非相似度** | 分数越小越相似，比较时用 `<=` 阈值 |
| 16 | 删了页面但还能搜到 | 向量库里留了 ghost 记录 | `embed.py --rebuild` 重建；`health.py --check zvec_ghost` 可查 |
| 17 | 新增页面搜不到 | 建了文件但没建索引 | 编译流程会自动索引；手动加的文件要跑 `#index` |
| 18 | 概念页在实体搭桥里"失联" | 实体索引不会自动更新 | 手动改文档后跑 `entity_index.py --rebuild` |
| 19 | 索引数据在你不期望的位置 | 索引/缓存默认落在 `<data_root>/.llm-wiki/` | 随数据走（便于整体备份）；可加进 `.gitignore` |
| 20 | 大库检索变慢 | 全量扫描或缓存失效 | 用增量模式 `embed.py --incremental` |

## 四、编译与模板

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 21 | 页面解析失败 / 控制台异常 | YAML frontmatter **必须在文件第一行**，且不能用 ```yaml 包裹 | 检查文件头 |
| 22 | 短内容被误判为长文（或反之） | 模板判定只看篇幅 | 判定优先级是**先看内容形态**（工具/产物 > 观点/知识），再看篇幅 |
| 23 | 概念页泛滥，全是工具名 | 概念判定标准没严格执行 | 三条硬条件必须同时满足：抽象性 + 可复用性 + 可定义性；工具名/产品名/人名不建概念页 |
| 24 | 一篇文章硬凑出好几个概念 | 把"宁缺毋滥"忘了 | **一篇文章可以零概念**，不硬凑 |
| 25 | 编译产物里出现了营销内容 | 没做文章价值预判 | 编译/带读前先判作者利益关联、私货浓度；营销段落标注"不提炼" |
| 26 | 同一个内容编译了两遍 | 去重层看错了地方 | 去重比对的是 **`raw/` 里源文件的 `source:` 字段**，不是 `wiki/`（编译产物的 source 是平台名） |
| 27 | 图片笔记的正文搜不到 | 正文在图里，OCR 产物没并入 | 同前缀的 `_img_N.md` 视为同一篇，合并进编译产物 |
| 28 | 英文内容没翻译 | LLM 未配置 | 翻译是可选增强；未配 LLM 时保留原文照常入库 |

## 五、双链与概念（知识网络）

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 29 | 双链莫名其妙，两篇其实无关 | 用相似度分数当建链判据了 | **分数只是召回工具**。只有 5 种关系才建链：补充 / 推翻矛盾 / 对比 / 时序演化 / 同主题互证 |
| 30 | 高分（>0.8）的文档该链接还是该合并？ | 接近重复 | >0.8 归入语义去重（合并），不是建链 |
| 31 | 页面显示为灰色（断链） | 目标文件名写错了（含特殊引号/异体字） | 复制真实文件名的码点，不要手打引号 |
| 32 | 图谱被"提示词文件"污染 | 提示词/模板文件里写了 `[[双链]]` 示例 | 提示词里描述文件名要用文字（如"某某文件（双链）"），不要写真的双链语法 |
| 33 | 孤儿页面很多，越补越乱 | 为了消孤儿而强行补链 | **是孤儿就是孤儿**，不强行补链；但**规范链缺失必须补**（如概念页必须有"来源：宿主页"） |
| 34 | 概念页与总结页定义不一致 | 概念页重写后没有回头改引用它的文档 | `#lint` 专门查这类差异 |

## 六、采集与去重

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 35 | 同一个视频入库两次 | 短链与长链字符串匹配不上 | **必须按 `video_id` 判重**（账本已处理；自建流程时注意） |
| 36 | 链接明明收录过却又抓了一遍 | 查重放在抓取之后 | 去重要在**抓取前**做（省时间也省额度） |
| 37 | 平台抓取突然全线失败 | 平台页面/接口改版 | 抓取链路本就是脆弱的，报错时先查是不是改版；本项目抖音链路已做过两次适配 |
| 38 | 抓取到的正文是空的/登录页 | cookie 失效或未登录 | 重新登录平台；多数平台需要有效登录态 |
| 39 | 转录稿有大量谐音错字 | ASR 固有误差 | 用规则纠错词表 + LLM 分段校对（本项目抖音链路内置）；**所有视频稿都建议过一遍校对** |
| 40 | 校对结果为空但没报错 | 推理型模型的长文本 thinking 耗尽了输出 token | 校对请求关闭 thinking，或改用非推理模型 |

## 七、宿主与自动化

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 41 | Agent 完全不按指令流程走 | 入口文件没被读到 | 确认 Agent 读的是 `CLAUDE.md` / `AGENTS.md`（或其约定的入口） |
| 42 | 定时任务没跑 | 宿主没开机 / cron 服务未启动 | 检查宿主的调度器状态；日志里会有 lateness 记录 |
| 43 | 定时任务跑了但结果没送达 | 通知渠道配置问题 | 检查任务的通知目标配置 |
| 44 | 依赖某个 skill 的步骤在别人机器上失效 | 那个 skill 是宿主侧的、未随仓库分发 | 指令里的 skill 引用一律写成"可选增强：有则用，无则跳过" |
| 45 | 「命令报成功但实际没生效」 | 部分 API 对无效参数静默接受 | 关键写操作**必须回读验证**（例如授权后查成员列表） |
| 46 | 提交时把别人的改动一起带进去了 | 工作区长期累积未提交改动 | 提交前 `git diff HEAD -- <file>` 量化确认；不要 `git add .` |
| 47 | 两个不同来源的改动混在一个提交里 | 攒太久，来历分不清 | 每轮操作完随手提交；一旦混了就按 mtime + diff 特征重新分批 |

## 八、Windows 特有

| # | 症状 | 原因 | 对策 |
|---|---|---|---|
| 48 | 终端输出乱码（CJK 混排、重复字符） | MSYS/Git-Bash 编码问题 | 命令写短一点；输出异常就立刻停下重试简单命令 |
| 49 | 子进程读 UTF-8 输出崩溃 | Windows 默认用 GBK 解码 | Python `subprocess` 显式传 `encoding="utf-8", errors="replace"` |
| 50 | 中文路径传给原生程序报"找不到" | MSYS 路径转换被禁用 | 传 `D:/x/y` 正斜杠原生路径，或程序内部用 `pathlib` 构造 |
| 51 | 提示词里写的多条命令只跑第一条 | 不同 shell 的换行/连接符语义不同 | 一次一条命令；或用 Agent 逐条执行 |
| 52 | OCR 静默返回"未识别到文字" | pytesseract 因环境问题导入失败 | 用项目 venv；`PYTHONPATH=""`；单独测 `import pytesseract` |

## 排查总口诀

1. **先看 `config.py` 自检** —— 引擎根、数据目录、集成开关、LLM 是否识别
2. **再看 `search.py` 的 `backend` 字段** —— `zvec` 正常 / `bigram` 说明向量链路坏了
3. **跑 `health.py`** —— 纯确定性检查，零 LLM 调用，能查出断链/索引漂移/幽灵记录
4. **LLM 步骤集体失败** → 先查解释器（PyYAML），再查 key/base_url，最后查模型是否被网关拒绝
5. **平台抓取失败** → 先怀疑平台改版，再怀疑登录态
