# LLM Wiki 使用指南

> 写给重新学习的自己。从零开始，一步步学会用这个知识库。
>
> ⚠️ **维护提醒**：wiki 项目有增删或调整时，必须同步更新以下两个文档：
> - `docs/quickstart.md` — 使用指南（指令表、场景示例、FAQ）
> - `docs/architecture-flowcharts.md` — 架构与全链路流程图

---

## 一、这个知识库是什么

一句话：**你存文章进来，AI 帮你编译总结、深度讲解、复盘沉淀、自动关联。**

它不是收藏夹，而是**学习引擎**——存进来的每篇文章都会被消化、和已有知识产生关联、沉淀成你自己的认知体系。

---

## 二、知识库长什么样

**用任何工具打开知识库目录都行**（Obsidian / VS Code / Typora / 文件管理器）：

```
<你的知识库目录>/
├── 00-INBOX/              ← 📥 待处理（新文章 / PDF / 截图放这里）
├── wiki/
│   ├── summaries/         ← 📄 总结页（编译产物，核心主干，按分类存放）
│   │   ├── AI & 技术/
│   │   └── 个人成长/
│   ├── concepts/          ← 🧠 概念页（编译时自动提取）
│   ├── conversations/     ← 💬 深度解读版（#distill 产出）
│   ├── evergreen/         ← 🌲 常青综述（#evergreen 产出）
│   ├── ideas.md           ← 💡 待深挖灵感池（复盘中冒出的延伸话题）
│   ├── overview.md        ← 📊 全库综合概述（自动维护）
│   └── index.md           ← 📋 页面索引（自动维护）
├── raw/                   ← 📦 原始文件归档（编译后自动移入，不用管）
├── github-stars/          ← ⭐ GitHub 星标收藏（可选，#stars 触发同步）
├── .llm-wiki/             ← 🔬 索引与缓存（向量库等，自动维护）
├── purpose.md             ← 📝 知识库目的声明（编译时会注入上下文）
└── wiki_log.md            ← 📝 操作日志
```

> **这些目录不用你手动建。** 安装器会自动创建（幂等：已存在的不动、不覆盖）。
> 就算你跳过安装器直接跑脚本，脚本也会在需要时自动补齐缺的目录。

**你日常只需要关注两件事**：

1. `00-INBOX/` — 放新内容（或者干脆把链接发给 AI，让它自己抓）
2. 跟 AI 对话 — 发指令操作

> **没装 Obsidian？完全不影响使用。** 知识库就是一个装满 Markdown 的普通文件夹。
> Obsidian 提供的是双链图谱和更好的阅读体验，属于加分项，不是必需品 ——
> 用 VS Code、Typora、甚至文件管理器都能看，**不打开它也不影响任何功能**
> （编译、检索、带读全部靠你跟 AI 对话完成）。
>
> 想用 Obsidian 的话：安装后选「打开文件夹作为仓库」，指向你的知识库目录即可，
> **不需要在 Obsidian 里"新建仓库"**。

## 三、一篇文章的完整生命周期

一篇文章从放进来到完全内化，经历以下状态：

```
📥 放入 00-INBOX（支持 PDF/DOCX/PPTX/图片/Markdown）
    ↓
⚙️ #ingest 编译（自动格式转换→生成总结+提取概念+归档原文+RAG索引）
    ↓ 状态变为 compiled
    │
    ├── 想深度消化 → #start → 四步带读 → #复盘 → 💎 distilled（沉淀完毕）
    │                                                  │
    │                                                  └── 可选 → #evergreen → 🌲 常青综述
    ├── 已经懂了，直接沉淀 → #复盘 → 💎 distilled（跳过带读，够用）
    │
    ├── 不想看 → #archive → 🗑️ archived（归档）
    │
    └── 暂时不管 → 安静待着，不打扰你
```

**关键理解**：
- `#start` 不是必须的，它是深度消化的路线
- 大部分文章编译后就停在 `compiled` 状态，不会强迫你立刻操作

## 五、实操场景：从零开始用

### 场景1：存一篇新文章进来

**步骤**：

1. **把文章放进 00-INBOX/**
   - 最简单：直接拖 .md 文件进去
   - 网页文章：用 Obsidian Web Clipper 浏览器插件一键保存
   - PDF/DOCX/PPTX：直接放进去，`scripts/convert.py` 会自动转成 Markdown

2. **告诉 AI 编译**
   - 在你的 Agent 对话里说："编译新文章"或"执行编译"
   - AI 会读取 `system/PROMPT.md` 的编译流程：
     - Step 1：读取知识库上下文（已有概念、overview、purpose）+ 英文自动翻译
     - Step 2：分析原文——提取了什么概念？和已有内容什么关系？（6类分析关系：引用/补充/推翻/对比/时序/包含层级）
     - Step 3：生成总结文档 + 概念页（按2026-08-02判定标准：3条件抽象性/可复用性/可定义性，排除工具/产品/人名/项目名，可零概念不硬凑；已有概念重写而非追加）+ 关联文档双链 + Unlinked References 补链
     - Step 3.5：**实体索引写入**——提取编译时已有的概念列表+一句话核心概括，写入 entity_index.db，零额外LLM调用
     - Step 4：**RAG 索引**——自动生成向量并入库 Zvec，入库后立刻可搜
     - Step 5：**语义去重检测**——如果新文档和已有文档内容高度相似，提醒你是否合并
     - Step 6：**增量关联与进化**——5类关系全自动处理+无关系跳过（2026-08-02修订）：补充→自动融入已有文档正文+建双链，推翻→标记矛盾，对比/时序→注明关系+双向建链，同主题互证→双向建链，无关系/主题擦边→不建链。无需确认，质量由每周自动审查兜底
     - Step 7：更新 overview.md 和 index.md
     - Step 8：检测隐含关联 + 语义匹配建议建链
     - Step 9：**分类路由校验**——自动检查 YAML category 和实际目录是否一致，不一致则自动修正

3. **结果**
   - 原文归档到 `raw/`
   - 总结文档出现在 `wiki/summaries/[分类]/`
   - 新概念出现在 `wiki/concepts/`
   - 文章状态为 `compiled`
   - 如果新文章补充了已有文档 → 已有文档正文自动融入新信息（重写对应段落）
   - 如果新文章与已有文档相关 → 自动建立双向链接

### 场景2：搜索已有内容

```
你：#search 信息过载
AI：🔍 搜索完成！找到 3 篇相关文档：
  1. [[间隔重复-遗忘曲线与记忆调度]] — 记忆衰减规律与复习时机
  2. [[主动回忆]] — 与之互补的提取练习
  3. [[每日复盘清单-五分钟三问]] — （相关性较低）
```

**搜索原理**：Zvec 混合检索（jieba FTS 关键词 + 向量语义 + RRF融合）+ 双链邻居扩展 + 实体搭桥扩展，四级流水线：
- **FTS 路径**：jieba 专业分词 + BM25 打分，搜"信息过载"能精确匹配标题/正文
- **向量路径**：把查询转成384维向量，找语义最相近的文档——搜"信息过载"能找到"认知Commons"（字面不同但意思相关）
- **RRF 融合**：两路排名合并，取长补短
- **双链扩展**：从搜索结果中的 `[[双链]]` 扩展到关联文档
- **实体搭桥**：从搜索结果中提取概念实体，通过共享实体找到双链没覆盖的关联文档——搜"认知Commons"能沿"注意力经济"这个实体跳到"慢速内容"

**降级**：Zvec 不可用时自动降级到 CJK bigram 搜索，不会报错。

### 场景3：问知识库问题

```
你：#ask 认知Commons是什么
AI：[⚡系统拦截：正在严格执行 #ask 流程...]

    📊 问诊结果：simple | 覆盖度：0.8 (complete)

    认知Commons是公共信息环境，类似于信息的"水源"。
    社交媒体、新闻等公共信息源共同构成这个"水源"，
    污染这个水源会导致整个社会的认知能力下降。

    📎 来源：[[认知Commons]]
    ⚠️ 观点冲突：[[慢速内容]]认为主动应对可行，[[注意力经济]]认为结构性问题难以个人层面解决
```

```
你：#ask 怎么建立长期的阅读习惯
AI：[⚡系统拦截：正在严格执行 #ask 流程...]

    📊 问诊结果：complex | 覆盖度：0.6 (partial) | 缺口：复习时机

    你想要哪种？
    1) 帮我列出来 — 每篇讲了什么 + 它们之间的关系
    2) 总结成文档 — 整合多文档，串联逻辑
    3) 给我实操步骤 — 从知识库内容推导出可执行步骤

    ⚠️ 知识库对"复习时机"覆盖不足，要不要我去网上搜一下补充？
```

**关键**：
- **简单问题**（"X是什么"）→ 直接回答 + 引用来源
- **复杂问题**（"怎么做XX"）→ 先引导确认你要什么形式，再深度整合
- **对比问题**（"X和Y什么关系"）→ 直接对比分析
- **覆盖不足** → 主动建议你去网上搜索补充（`#research`）
- 所有回答标注来源，不编造

### 场景4：深度带读一篇文章

```
你：#start 认知Commons
AI：[⚡系统拦截：正在严格执行 #start 流程...]

    📂 数据源装载状态：
    - 📄 摘要层：已读取 [[认知Commons]]
    - 🗄️ 原文层：已读取 [[源文件]]

    📎 相关推荐：和本文语义相关的文档：
    - [[主动回忆]] — 语义相似度最高
    - [[费曼技巧]] — 讨论同一主题的不同角度
    - ⭐ ai-agents — 你收藏的项目：AI 智能体资源清单（github-stars）

    带 ⭐ 的是你 GitHub Stars 收藏的项目，适合对照实践。

    🎯 核心主旨：公共信息环境正在被注意力经济污染

    💡 核心论点：
    1. 认知Commons正在被污染
    2. 慢速内容对抗快速内容
    3. 意义经济将取代注意力经济

    🗺️ 全文脉络：[逻辑结构拆解]

    接下来我将把全文拆解为 X 个逻辑模块，逐段精读。主动权在你——每段讲解后你有疑问随时提问，觉得懂了就回复 1 或"继续"推进。
    准备好进入【第一模块】了吗？
```

**四步带读法**：
0. **已沉淀过滤**（防重复带读）：先跑 `check_distilled.py --check "<标题>"`，已带读/已沉淀（status=distilled / interaction_count≥1 / conversations/ 有 Chat 文件）则拦截，除非用户明确"重读"；确认开始带读时跑 `--mark` 打标记（interaction_count+1），形成防重复闭环
1. **全局拆解**：一句话核心主旨 + 3个关键观点 + 全文脉络 + **相似文档推荐**（自动推荐语义相关的其他文档）
1.5. **📋 文章价值预判**（防营销浪费时间）：双重读取后输出价值评估卡——分级（🟢纯知识/🟡知识为主带私货/🟠营销为主/🔴水文）+ 营销信号证据（作者利益关联/结构套路/私货浓度/可验证性/转化浓度）+ 建议（值得读/只读知识/不读转#archive）；用户决策后才进入拆解。营销段落不提炼不深读，复盘时沉淀 ⚠️私货排除区 + frontmatter intent 标记（详见 start.md 阶段一）
2. **逐段精讲**：贴原文 + 大白话翻译 + 底层逻辑 + 现实比喻 + **用户主导答疑**（AI 不主动抛问题，只确认理解+问"有无疑问"，用户提问则紧扣内容解答，超原文推演标注来源归属）
3. **认知体检**：问你是否还有模糊的地方
4. **发散延伸**：脱离文本，探讨暗线和跨界应用

**操作技巧**：
- 回复"过"或"继续"→ 跳到下一段
- 回复"1"→ 同上
- **主动权在你**：每段拆解完 AI 只确认理解并问有无疑问，你没问题就推进；有疑问随时提问，AI 紧扣内容回答
- **延伸分流**：你延伸跑题时 AI 先接住再拉回主线（带读中不处理，无需你 cue"记一下"）；复盘时自动识别对话历史——与文章相关的进对话增量区，无关但有价值的收进 conversation 文件的「🧭 延伸话题」板块 + 同步 `wiki/ideas.md`（集中索引，带双链，AI 可检索；按需升级，不预建文件）

### 场景7：知识织网

```
你：#bridge
AI：🕸️ 织网雷达发现 2 对隐含关联：

    1. [[认知Commons]] ↔ [[注意力经济]]
       理由：注意力经济是认知Commons污染的主要来源
       建议：在 [[认知Commons]] 添加 → [[注意力经济]]

    2. [[慢速内容]] ↔ [[注意力经济]]
       理由：慢速内容是对抗注意力经济的策略
       建议：在 [[慢速内容]] 添加 → [[注意力经济]]

    回复数字确认单条，或回复"全部确认"
```

**织网 vs 入库关联的区别**：
- `#ingest` Step 6：**入库时**即时处理新文档与已有文档的关系（自动融入补充、建双链、标矛盾）——增量操作，全自动
- `#bridge`：**全库级别**扫描，发现所有应该关联但没关联的文档对——全局织网

**自动审查兜底**：每周 `#lint` 自动审查最近7天自动进化的内容，发现问题自动修正，拿不准的才推送给你。

```
AI：⭐ GitHub Stars 同步开始...
    📍 拉取star列表：160+个项目
    🔍 去重对比：新增2，跳过已有，取消star：0
    📥 处理2个新增项目...
    ✓ 入库完成

    新增项目：
    1. xxx/yyy — AI视频剪辑工具（分类：ai-agents）
    2. zzz/www — 简历生成器（分类：resume-career）
```

**同步做了什么：**
1. 调GitHub API拉取你当前的star列表
2. 和库里已有项目做对比（用 `repo` 字段去重）
3. 新增的 → 读README前200行 → LLM打中文描述+标签 → 自动分类 → 生成md入库
4. 已有的 → 跳过
5. 取消star的 → 标记归档
6. 自动建立向量索引（同步完立即可搜）

**增量更新**：只有第一次是全量，后续只处理新增的几个项目，几秒钟搞定。零token消耗（对比是纯字符串比较）。

**分类逻辑**（三层兜底）：
1. 已有分类映射表 → 精准分类
2. 描述关键词推断 → 推断分类
3. LLM从已有分类中选 → 不新建乱分类
4. 都不行 → other

## 七、知识看板

双击打开 `index/dashboard.html`（浏览器自动打开），这是知识库的**可视化控制台**。

```bash
python scripts/dashboard.py
```

每次编译、复盘、归档后跑一次，看板数据就会刷新。也可以在 AI 对话里说"更新看板"。

### 看板区域说明

| 区域 | 展示什么 | 你怎么看 |
|------|---------|---------|
| **KPI 条** | 核心数字：待入库 / 概念 / 总结 / 素材 | 一眼扫过去，知道知识库整体规模 |
| **状态** | 已编译/带读中/已沉淀/已归档 各多少 | 关注"已编译"数量——这些是等着你决定的 |
| **概念** | 按分类展示所有概念芯片 | 看看概念有没有分类空缺（"未分类"太多说明编译时漏填） |

| **孤岛** | 没有任何文章引用的概念 | 用 `#bridge` 发现关联 |
| **健康** | 断链、孤儿页面等结构性问题 | WARN 需要修，INFO 可以忽略 |
| **过期 >30天** | 编译超过30天还没深度阅读的文章 | 提醒你是不是该 `#start` 或 `#archive` 了 |
| **常青** | 跨文章的体系综述文档 | 知识库最高层的结晶 |

### 看板数据从哪来

所有数据由 `scripts/dashboard.py` 实时扫描知识库文件生成，不依赖 Obsidian Dataview，不消耗 LLM token。

### 什么时候看

- **编译新文章后** → 看KPI和状态有没有更新
- **每天打开知识库时** → 看过期区有没有积压
- **跑完 health.py 后** → 看健康区有没有新问题

## 九、RAG 搜索详解

### 技术架构

```
用户查询 "信息过载"
    ↓
┌─────────────────────────────────────┐
│  Zvec MultiQuery（并行两路）          │
│                                     │
│  路径1: FTS全文检索                   │
│    jieba分词 → BM25打分              │
│    "信息/过载" 匹配标题和正文          │
│                                     │
│  路径2: 向量语义搜索                  │
│    query→384维向量 → HNSW近邻搜索     │
│    "信息过载"≈"认知Commons"（语义近）   │
│                                     │
└─────────────────────────────────────┘
    ↓
RRF 融合（内置 RrfReRanker）
    ↓
Top-K 结果
```

### 组件清单

| 组件 | 作用 | 成本 |
|------|------|------|
| Zvec 0.5.1 | 向量数据库（FTS+向量+RRF） | ¥0，12MB |
| fastembed 0.8.0 | 本地embedding推理（ONNX） | ¥0 |
| multilingual-MiniLM-L12-v2 | 多语言embedding模型 | ¥0，约 241MB（一次性下载） |
| onnxruntime 1.20.1 | ONNX推理引擎 | 已安装 |

**全本地运行，零API调用，零费用，支持离线。**

### 内存占用

| 时机 | 内存 |
|------|------|
| 搜索时（临时加载模型） | 峰值~650MB，用完释放到~80MB |
| 不搜索时 | ~80MB基础 |
| Zvec数据库 | 几MB（随文档量线性增长） |

### RAG 赋予的6个能力

| 能力 | 触发方式 | 效果 |
|------|---------|------|
| **语义搜索** | `#search` 自动生效 | 搜"信息过载"能找到"认知Commons"（字面不同但意思相关） |
| **相似文档推荐** | `#start` 带读时自动触发 | 读"认知Commons"时自动推荐"慢速内容"，也会推荐你收藏的相关 GitHub 项目（带⭐标识） |
| **智能问答** | `#ask` 自动生效 | ask.py判断复杂度：simple直接答，complex先引导确认再深度整合，comparative对比分析。覆盖不足时主动建议搜索 |
| **语义去重检测** | `#ingest` 入库时自动检测 | 新文档和已有文档语义重复时提醒你合并 |
| **增量关联与进化** | `#ingest` 入库时自动执行 | 5类关系全自动处理+无关系跳过（补充→融入正文+建双链，推翻→标矛盾，对比/时序→双向建链，同主题互证→双向建链，无关系/主题擦边→不建链），质量由 `#lint` 每周审查兜底 |
| **实体搭桥扩展** | `#search`/`#ask`/`#start` 自动生效 | 通过共享概念实体发现双链没覆盖的隐含关联——两篇文档共享2个以上概念时自动搭桥，共享1个但双方都是核心主题也搭桥，高频通用实体自动降权 |

### 索引管理

日常不需要手动操作——`#ingest` 编译时自动索引。如果出问题：

| 你说 | 我执行 | 场景 |
|------|--------|------|
| `#索引` | 增量索引（只处理变化的） | 日常补索引 |
| `#索引 全量` | 扫描所有wiki页面 | 确认全覆盖 |
| `#索引 <文件名>` | 单文件索引 | 指定文件补索引 |
| `#索引 重建` | 删旧索引从零重建 | 索引损坏时修复 |
| `#索引 统计` | 查看Zvec状态 | 看看索引了多少篇 |

### 降级策略

| 场景 | 降级方案 | 效果 |
|------|---------|------|
| Zvec数据库损坏/丢失，或 fastembed 模型加载失败 | 自动降级 CJK bigram 搜索（+双链邻居扩展） | 只匹配字面，语义搜索不可用 |
| entity_index.db损坏/丢失 | 跳过实体搭桥，只走Zvec+双链 | 搜索正常，但跨文档关联发现能力降级 |
| 都不可用 | 宿主 Agent 直接读文件判断（Agent 层兜底） | 最原始但保证可用 |

### Zvec 索引范围

embed.py 索引的目录（即 Zvec 能搜到的范围）：

| 目录 | 内容 | type 字段 | 搜索权重 (SOURCE_TIER) |
|------|------|-----------|----------------------|
| `wiki/evergreen/` | 体系综述 | synthesis | **1.4**（最高） |
| `wiki/concepts/` | 概念页 | concept | **1.3** |
| `wiki/summaries/` | 总结文档 | source | **1.0** |
| `github-stars/` | GitHub Stars 项目 | github-star | **0.8**（最低） |
| `wiki/conversations/` | 深度解读版 | distill | **1.15** |
| `github-stars/` (archived) | 已归档Stars项目 | github-star-archived | **0.5**（最低） |

**权重含义**：同样匹配度下，synthesis（体系综述）排最前，github-star-archived 排最后。

### 各指令的搜索范围

不同指令搜不同内容，不是所有都全量搜：

| 指令 | 搜索范围 | 排除 | 说明 |
|------|---------|------|------|
| `#start` | summaries + concepts + evergreen + github-stars | 无 | 带读时推荐相关工具（⭐标识） |
| `#复盘` | summaries + concepts + evergreen + github-stars + conversations | 无 | 深度解读版写入conversations，关联收藏项目 |
| `#search` | 全量（所有目录） | 无 | 通用搜索不设限 |
| `#ask` | 全量（所有目录） | 无 | 通用问答不设限 |
| `#ingest` | summaries + concepts + evergreen | 无 | 入库关联只看知识库内容 |

实现方式：`search.py` 的 `--exclude-type` 参数，如 `--exclude-type github-star`。

## 十、健康检查

看板的"健康"区已经展示了健康检查结果。如果想在终端看详细输出：

```bash
python scripts/health.py
```

输出示例：
```
LLM Wiki Health Check
Status: WARNING
Pages: 33
Issues: 2 (0 errors, 1 warnings, 1 info)

broken_link:
  ⚠️ [[意义感]] points to non-existent page

orphan_page:
  ℹ️ Page 'xxx' has no inbound wikilinks (orphan)
```

**8 项检查**（0 LLM 调用，秒级跑完）：

| 检查项 | 怎么找的 | 严重级别 |
|--------|---------|---------|
| broken_link | 扫描所有 `[[双链]]`，检查目标页面是否存在 | WARN |
| empty_file | 检查文件大小是否为0 | ERR |
| index_sync | 对比 wiki/index.md 条目和实际文件 | WARN |
| log_coverage | 对比 wiki_log.md 记录和实际文件 | INFO |
| orphan_page | 检查没有任何入链的页面 | INFO |
| category_routing | 检查 YAML category 与实际目录是否一致，不一致自动修正 | INFO/WARN |
| entity_index | 检查实体索引数据库一致性（stale chunks / missing pages / mention_count异常） | INFO/WARN |

**WARN** = 需要关注（断链、索引不同步）
**INFO** = 提示性（孤儿页面、日志缺失）
**ERR** = 严重问题（空文件）

## 十四、常见问题

**Q：文章放进 00-INBOX 后没反应？**
A：需要告诉 AI "编译新文章"，AI 才会执行编译流程。或者设置 `scripts/watch.py` 持续监听。

**Q：搜索找不到相关内容？**
A：当前搜索是 Zvec 混合检索（jieba FTS + 向量语义 + RRF融合）。即使关键词和文档内容字面不同但语义相关（如"信息过载"能找到"认知Commons"），向量搜索也能识别。如果完全搜不到，试试换个关键词，或用 `#索引 增量` 确认文档已索引。

**Q：#ask 回答说"未收录"？**
A：知识库里确实没有相关内容。可以用 `#research 主题` 从网上搜索补充。

**Q：编译时概念重复创建了？**
A：不应该发生。两步编译的 Step 2 会先分析已有概念，Step 3 只对已有概念建双链、新概念才新建页面。另外 Step 5 会做语义去重检测，如果新文档和已有文档内容高度相似会提醒你。如果遇到问题，检查 `wiki/index.md` 是否和实际文件同步。

**Q：想换用别的 Agent？**
A：在那个 Agent 里打开本项目即可 —— 它会读入口文件（`CLAUDE.md` 或 `AGENTS.md`），指令完全一样。

**Q：搜索索引出问题了怎么办？**
A：用 `#索引 重建` 从零重建索引。日常 `#ingest` 编译时会自动索引新文档，一般不需要手动操作。

**Q：RAG 搜索要花钱吗？**
A：不用。所有 embedding 向量都是本地生成（fastembed + ONNX Runtime），零 API 调用，零费用，支持离线。

**Q：RAG 搜索占多少内存？**
A：搜索时临时加载 embedding 模型（峰值~650MB），生成完 query 向量后自动释放到~80MB。Zvec 数据库本身只占几MB。日常不搜索时几乎不占内存。

**Q：GitHub Stars 同步要花token吗？**
A：增量对比零token（纯字符串比较）。只有新增项目需要token：读README（免费，GitHub API）+ LLM打中文描述和标签（LLM_API_BASE/KEY/MODEL 配置的模型，每个项目约100 token）。增量更新通常只新增几个项目，几秒钟搞定。

**Q：搜GitHub Stars项目搜不到？**
A：三个原因：①搜索词和标签/描述都不匹配，换个关键词试试；②项目被分到了 `other/` 分类，分类不准可以手动调整；③向量索引可能损坏，跑 `#索引 重建` 修复。

**Q：GitHub Stars项目分类不准怎么办？**
A：直接移动md文件到正确的分类目录，然后修改文件里 `category` 字段。脚本下次同步会跳过已有项目，不会覆盖你的调整。

**Q：新文章入库后已有文档会自动更新吗？**
A：会。如果新文章补充了已有文档的信息，已有文档正文会自动融入新信息（重写对应段落），同时建立双向链接。所有操作全自动，不需要确认。每周 `#lint` 自动审查会检查这些自动变更的质量，发现问题自动修正。

**Q：英文文章放进 INBOX 会自动翻译吗？**
A：会。`convert.py --inbox` 自动检测英文文件，调用 Google Translate 翻译为中文版（`.zh-cn.md`），编译时使用中文版，英文原文归档到 `raw/`。还会用 LLM 做术语校验（需配置 `LLM_API_KEY` 环境变量，没配则跳过校验）。

**Q：embed.py / search.py 报错 No module named 'zvec._zvec'？**
A：需要用独立venv运行，命令：`PYTHONPATH="" .venv/Scripts/python.exe scripts/embed.py`。不要直接用 `python scripts/embed.py`，因为宿主环境的 zvec 与本项目 Python 版本不匹配（各自编译的二进制扩展不通用）。



**Q：conversations 目录里的文件有用吗？**
A：有用。它存的是 `#复盘` 的深度解读版，已纳入 Zvec 索引（SOURCE_TIER 1.15），可被搜索命中。深度解读版包含完整的推演过程和精华提炼，搜索和写作时都能作为高质量素材来源。源文件底部沉淀区保留指向 Chat 文件的链接，可跳转查看完整推演。


**Q：不同类型页面的搜索权重怎么排？**
A：`SOURCE_TIER` 从高到低：`synthesis`（常青综述）1.4 > `concept`（概念页）1.3 > `entity` / `topic` 1.2 > `distill`（深度解读版）1.15 > `snippet` 1.1 > `source`（总结页）1.0 > `github-star` 0.8。常青综述权重最高 —— 它是多篇交叉提炼出的结论层。
