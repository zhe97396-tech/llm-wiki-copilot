# 密钥与数据安全

> **一句话：你的密钥不会被提交、不会被打印，而且不配也能用。**

这个项目会用到**可选**的密钥。本文说明它们是什么、放哪里、以及本项目对它们做了什么处理
（每一条都附了你可以自己跑一遍的验证命令）。

---

## 一、需要哪些密钥（全部可选）

| 密钥 | 用途 | 不配的后果 |
|---|---|---|
| `LLM_API_KEY`（+ `LLM_API_BASE` / `LLM_MODEL`） | 英文文档翻译、GitHub Stars 中文标签、视频稿 LLM 校对 | 这些步骤**自动跳过**，核心功能（编译/检索/带读/沉淀）完全不受影响 |
| `GITHUB_TOKEN` | 提高 GitHub API 速率限制 | 只读公开 star 也能用，只是有速率限制 |
| `XHS_COOKIE` 等平台登录态 | 小红书等平台的抓取 | 该平台抓取不可用 |

**任何 OpenAI 兼容端点都可以**（OpenAI / DeepSeek / 本地 Ollama / 各类网关）。

---

## 二、怎么提供（优先级从高到低）

### 方式 1：环境变量（推荐，最不容易误提交）

```bash
LLM_API_BASE=https://api.deepseek.com/v1
LLM_API_KEY=你的key
LLM_MODEL=deepseek-chat
GITHUB_TOKEN=你的token
```

### 方式 2：项目 `config.yaml` 的 `llm` 段（安装向导会生成）

```yaml
llm:
  base_url: "https://api.deepseek.com/v1"
  api_key: "你的key"
  model: "deepseek-chat"
```

> **`config.yaml` 在 `.gitignore` 里，永远不会被提交。**

### 方式 3：借用宿主 Agent 的配置（如果你用 Hermes 等宿主）

脚本查找密钥的顺序是：**环境变量 → 项目 `config.yaml` → 宿主 Agent 的配置**。

第三层是「零配置兼容」：如果你的宿主（如 Hermes）已经配好了模型，本项目直接复用，
你不用再填一遍。

> **透明度说明**：这一层会**读取宿主配置文件来获取 base_url 与 key**，
> 但**只读取这两项**，不读也不改宿主的其它配置；同样**从不打印 key 值**。
> 不希望它这么做的话，在项目 `config.yaml` 或环境变量里显式配好即可覆盖（优先级更高）。

### 方式 4：什么都不配

不配就走「降级模式」：需要 LLM 的环节自动跳过并**明确告知**，不报错、不静默失败。

## 三、本项目对密钥做了什么（附验证命令）

| 措施 | 自己验证 |
|---|---|
| `config.yaml`、`.env`、`*.local` 都在 `.gitignore` 里 | `cat .gitignore` |
| 配置模板里只有空占位符，没有任何真实值 | `grep -i "key\|token\|cookie" config.example.yaml` |
| **代码从不打印密钥值** —— 自检只显示是否设置与长度 | `python scripts/llm_api.py` → `api_key: SET(len=51)` 或 `EMPTY` |
| 生成的入口文件（CLAUDE.md / AGENTS.md）与斜杠命令文件里**不含**密钥 | `grep -i "api_key" CLAUDE.md AGENTS.md` |
| 缺密钥时优雅跳过（不是崩溃） | 不配任何 key 直接跑 `#ingest`，看日志 |
| 操作日志（`wiki_log.md`）只记操作与时间，不记配置 | 打开看一眼 |

**关键设计**：密钥在**引擎目录**的 `config.yaml`，你的知识在**数据目录**。
所以你把知识库目录分享/备份给别人时，**里面没有密钥**。

## 四、如果你怀疑密钥泄露了

按这个顺序做，**第 1 步最重要**：

| # | 动作 | 说明 |
|---|---|---|
| 1 | **立即去服务商后台吊销并重新签发** | 密钥一旦泄露，改历史也救不了已泄露的那份；吊销是从根上止损 |
| 2 | 检查是否写进了 git 历史 | `git log -p --all \| grep -iE "sk-\|ghp_\|api_key.*[A-Za-z0-9]{20}"` |
| 3 | 若已 push 到远端 | 吊销优先；改历史（filter-repo）是第二优先，别为了改历史耽误吊销 |
| 4 | 检查终端历史与截图 | `~/.bash_history`、聊天记录、截图、录屏 |
| 5 | 检查是否贴给过 AI 对话 | 对话历史也可能被留存 |

---

## 五、红线（写给你也写给 Agent）

- ❌ 不要把密钥写进**提示词文件、文档、提交信息** —— 这些东西会被 git 记录、会被分享
- ❌ 不要把 `.env` 或 `config.yaml` 拖进聊天窗口、不要截图
- ❌ 不要在 Issue / PR / 讨论区贴密钥（哪怕是"帮我看看为什么报错"）
- ❌ 不要用"看起来像占位符"的真实 key 提交（`sk-xxxx` 这种在扫描规则里也是命中项）
- ✅ 要分享配置给朋友时，分享 `config.example.yaml`（空模板），不要分享 `config.yaml`

---

## 六、如果要用在共享/服务器环境

| 场景 | 建议 |
|---|---|
| 多人共用一台机器 | 用环境变量而非 `config.yaml`，避免同机其他人读到文件 |
| 自动化 / 定时任务 | 把密钥放在任务的环境变量里，不要写进脚本 |
| 容器 / CI | 用平台的 secrets 机制，不要 `COPY .env` |
| 给别人演示 | 用降级模式（不配 key 也能完整跑核心链路） |
